# 设计原则与决策记录

## 设计原则

### 1. 不自残原则

**dead 设备永不自动重注册。**

服务端识别"被封就自杀"行为后会判定"你在跟服务端玩消耗战" → 升级到 IP 级 / 指纹级联合封禁。原版 v0.0.6 的 `replaceDevice()` 就是这种自杀模式。本 fork 改成"池内切换 + 手动补员 + 24 h 冷却"，把"批量注册"这种行为模式彻底拆掉。

### 2. 不存签名凭据到日志

`x-argus` / `x-ladon` / `x-ss-stub` 等签名头**不进**诊断日志。

理由：
- 签名凭据泄露给第三方等于把服务端黑产通道公开
- 用户复制日志去 issue 时容易误传
- 签名凭据本身生命周期短（服务端随时变），存日志没意义

诊断日志只记：请求方法、URL（去 query）、响应状态码、耗时、节流倒计时、设备 ID 后 6 位。

### 3. 不上报

**本 fork 不向任何第三方发送日志 / 统计 / 崩溃信息。**

- 全部状态在 IndexedDB + GM_setValue（本地）
- 日志只在用户主动复制时才离开浏览器
- 没有 google analytics、没有 sentry、没有埋点

上游 v0.0.6 的 `fetchHook` 会屏蔽字节 / 百度统计的埋点上报 —— 本 fork 保留这个能力，并**额外**确保自己的代码路径无任何上报。

### 4. 不打包票

服务端风控持续升级，本 fork 的设计目标是"用几个月不被封"，不是"永远"。

任何客户端绕法都有失效的一天 —— 当服务端风控升级到 IP + 设备指纹 + 行为分析的联合识别时，需要等上游签名算法更新。本 fork 不会承诺绕过此类升级。

### 5. 不破坏上游协议

- 沿用上游签名栈（L3 / L5）
- 沿用上游 license（GPL-3.0）
- 在 README / 注释 / 控制面板显著位置标注 fork 来源
- 上游 `fanqie-assistant-v0.0.6.user.js` 完整版作为应急 fallback 一起打包

### 6. 失败要给用户知情权

- 失败恢复弹窗：5 选项 + 诊断默认展开
- 控制面板可看：当前设备、节流倒计时、池子状态、最近日志
- 控制面板日志区"复制全部"按钮：一键粘贴到 issue

## 决策记录

### D1: 节流用正态分布而不是均匀分布（为什么是这个）

| 候选 | 优点 | 缺点 | 决策 |
|------|------|------|------|
| 固定间隔（如每次 15 s） | 简单 | 像机械心跳，一眼脚本 | ❌ |
| 均匀分布（5–25 s） | 简单 | 边界值太多，看起来像"刚切换" | ❌ |
| 指数分布 | 更像事件间隔 | 大量短间隔，少量长间隔 → 触发频率风控 | ❌ |
| 正态分布 | 中间多、两头少，更像真人 | 实现稍复杂（Box-Muller） | ✅ |

最终：Box-Muller 正态分布，均值 12 s（偏向短端，(5+25)·0.45 = 13.5 ≈ 12），stddev 5 s = (25−5)·0.25。3 % 概率插入 30–90 s 长停顿覆盖 L4 行为模拟。

### D2: 设备池 3 槽（为什么是这个）

| 候选 | 优点 | 缺点 | 决策 |
|------|------|------|------|
| 1 槽（沿用上游）| 简单 | 死了就死 | ❌ |
| 2 槽 | 够用 | 1 槽死了另 1 槽死了就停摆 | ❌ |
| 3 槽 | 容错 + 不浪费 | 多 1 次注册成本 | ✅ |
| 5+ 槽 | 容错高 | 服务端会盯"5 个设备同 IP" | ❌ |

最终：3 槽。理由：保证 1 个死亡、1 个 fallback、1 个新生成的备胎 + 同时不会触发"大量设备"的注册风控。

### D3: 启动错开注册（为什么是这个）

3 个设备在 1 s 内同时注册 → 服务端立刻识别为"脚本批量注册" → 整套设备池全封。

解决方案：槽 0 立即注册，槽 1 延迟 10 s，槽 2 延迟 30 s。这样注册时间散开，服务端看不到"批量"模式。

代价：首次启动后要等 30 s 才有 3 个设备可用。这 30 s 内只有槽 0 能用 → 用户**首次访问章节会等到槽 0 注册完成后才解锁**。这个延迟是可接受的。

### D4: 失败 2 次切下一槽（为什么是这个）

| 候选 | 优点 | 缺点 | 决策 |
|------|------|------|------|
| 1 次失败立即切 | 0 延迟 | 1 次网络抖动就切，浪费槽位 | ❌ |
| 2 次失败切 | 容错 + 避免误切 | 多等 5–25 s | ✅ |
| 3 次失败切 | 更稳 | 太迟，可能已经被服务端盯上 | ❌ |

最终：连续 2 次失败才切。理由：网络抖动很常见，1 次失败 80 % 是抖动；2 次连续失败才有 80 % 把握是设备问题。

### D5: 手动补员 24 h 冷却（为什么是这个）

| 候选 | 优点 | 缺点 | 决策 |
|------|------|------|------|
| 无冷却 | 自由 | 用户连点会触发批量注册风控 | ❌ |
| 1 h 冷却 | 灵活 | 太短，连点风险仍在 | ❌ |
| 24 h 冷却 | 跟服务端"设备重置"时间窗一致 | 略长 | ✅ |

最终：24 h。理由：服务端一般给设备重置窗口也是 24 h 量级，跟服务端节奏对齐，避免被服务端识别为"高频重置"。

### D6: Pin 配额 50 本 / 5000 章（为什么是这个）

| 候选 | 优点 | 缺点 | 决策 |
|------|------|------|------|
| 无配额 | 自由 | "我把整站都 pin 了" → 拉取行为像数据爬虫 | ❌ |
| 10 本 / 500 章 | 严格 | 太抠，正常用户不够用 | ❌ |
| 50 本 / 5000 章 | 够重度用户用 + 不触顶 | — | ✅ |
| 200 本 / 20000 章 | 几乎无限制 | 几乎等于"全站 pin" | ❌ |

最终：50 本 / 5000 章。50 本够重度小说爱好者同时追，5000 章够单本追完大部分网络小说（千章级）。

### D7: 控制面板默认 Popover（为什么是这个）

| 候选 | 优点 | 缺点 | 决策 |
|------|------|------|------|
| 默认侧栏 | 常驻可见 | 占阅读空间 | ❌ |
| 默认 Popover | 不占空间 + 可升级 | 需要点 ⚙️ | ✅ |
| 默认折叠按钮 | 极简 | 找不到 | ❌ |

最终：默认右下角 ⚙️ → 点击展开 Popover → 点 ⮮ 升级为侧栏。理由：阅读体验优先，需要时才展开。

### D8: 失败恢复弹窗诊断默认展开（为什么是这个）

| 候选 | 优点 | 缺点 | 决策 |
|------|------|------|------|
| 默认折叠 | 干净 | 出问题还要多点一次 | ❌ |
| 默认展开 | 立刻能看 | 视觉上占空间 | ✅ |

最终：默认展开。理由：失败弹窗本身就是异常状态，用户在这个时候就需要看日志。如果觉得视觉吵，手动折叠即可。

## 不做的事

- ❌ 不实现 TXT 文件下载（v0.1.0 精简策略不含；Pin 缓存覆盖"本地持久化"核心需求）
- ❌ 不实现听书 / 书架 / 搜索 / 评论（v0.1.0 精简策略不含；上游 v0.0.6 全功能版作为 fallback 提供）
- ❌ 不引入第三方 API（任何"接 XX 网站"都不做）
- ❌ 不实现 IP 轮换（超出用户脚本范围）
- ❌ 不实现浏览器指纹伪装（超出用户脚本范围，且效果有限）
- ❌ 不在 README / 控制面板承诺"永远不被封"
- ❌ 不绕过 GPL（上游 license 沿用，并标注 fork 来源）
